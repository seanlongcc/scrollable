# Product

## Register

product

## Users

Scrollable is for people who assemble temporary, media-heavy viewing sessions from user-provided URLs, Reddit post or listing links, and local files. They are often on phones or narrow screens, moving quickly between discovery, browsing, saving layout metadata, and full-screen viewing.

The core job is to turn a set of pasted or selected sources into a controlled, scrollable media workspace without giving up privacy or persistence boundaries.

## Product Purpose

Scrollable is a mobile-first reels-style feed viewer for runtime image, video, audio, gallery, Reddit, provider-embed, and local upload sources. It lets users arrange multiple feeds in fixed grids, free-form layouts, stacked layers, and satellite focus views.

Success means users can build and revisit layouts without Scrollable persisting, rehosting, proxy-caching, or owning third-party media payloads, thumbnails, extracted URLs, raw provider responses, or raw runtime IDs.

## Brand Personality

Technical, private, kinetic.

Scrollable should feel like a focused media instrument: direct, tactile, slightly underground, and built for continuous viewing rather than administration. The tone should be terse and useful, with privacy constraints treated as product confidence, not legal copy.

## Anti-references

Avoid generic SaaS dashboards, marketing hero layouts, pastel creator-tool blandness, neon cyberpunk overload, glassmorphism as decoration, AI-gradient spectacle, and card-grid sameness.

Avoid interfaces that imply Scrollable owns or hosts media. Avoid browse surfaces that expose saved third-party media previews when only configuration metadata should appear.

## Design Principles

1. Runtime media is the stage. Chrome should stay compact, thumb-reachable, and easy to hide.
2. Privacy should be legible in behavior. Saved views show configuration metadata, not third-party media previews.
3. Mobile is the primary control surface. Desktop adds density and precision, but must not fork the workflow.
4. Source complexity should unfold in layers. Users start with add, view, save, and adjust; advanced timing, layout, and cache choices appear when needed.
5. Brand should come from motion, restraint, and memorable details, not from decorative effects.

## Accessibility & Inclusion

Target WCAG 2.2 AA for interactive controls, dialogs, media navigation, keyboard support, focus states, contrast, and reduced motion. The viewer must remain usable without hover, with touch, keyboard, screen readers, zoomed text, and reduced-motion preferences.

Media performance and accessibility are linked: active media should load intentionally, inactive media should not create unnecessary CPU, network, or motion burden, and errors should be explicit without exposing third-party payload details.
